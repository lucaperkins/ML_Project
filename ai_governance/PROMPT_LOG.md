- **Goal:** Review the data preparation pipeline, identify remaining methodological issues and verify the handling of duplicate comments before training the baseline models.

**Original prompt (verbatim):**

**Retrospective English reformulation (not the original prompt):**

The Parquet export issue was resolved by restarting the Jupyter kernel. I have attached the updated data preparation notebook and the three generated Parquet files.

Please review the preprocessing pipeline, verify the recorded results, and identify any remaining methodological issues before proceeding to baseline training.

Focus on the following requirements:

- Preserve the multi-label structure of the GoEmotions dataset (27 emotions + Neutral).
- Verify that there is no data leakage between the training, validation and test sets.
- Assess the duplicate handling strategy and its impact on emotion annotations.
- Check the consistency and integrity of the exported datasets.
- Preserve the test set for final evaluation only.
- Justify each proposed modification and avoid unnecessary preprocessing.
- Explicitly identify any results that cannot be independently verified.

Suggest reproducible Python checks where necessary and provide a prioritized list of the remaining tasks to complete Week 2.

**Methodological constraints from the project discussion and retrospective reformulation:**

- Data schema: English comments with 28 possible labels (27 emotions + Neutral), organized into training, validation and test splits.
- Statistical assumptions: Emotion annotations are subjective, and identical texts may have different labels.
- Leakage guardrails: Prevent text overlap between splits and preserve the test set for final evaluation only.
- Fallback behaviour: Explicitly report unverifiable results and suggest reproducible Python checks before modifying the dataset.

**What we kept, what we rejected:**

We kept the existing preprocessing pipeline and added automated assertions to verify the absence of overlapping texts between splits.

We also added a calculation to identify duplicate comments with different emotion annotations and investigated the impact of merging their labels.

We decided not to automatically remove Neutral when it appears alongside another emotion, since this combination already exists in the original dataset.

Finally, we added checks to verify that the exported Parquet files could be reloaded correctly.

**How we verified the output:**

We implemented and executed the suggested checks in notebooks/01_eda_simple.ipynb.

The results on the previous lowercase-only pipeline showed that (the current emoji/repeated-letter pipeline must be rerun):

- All leakage assertions passed. No normalized text was shared between splits.

- 61 groups of duplicate training texts had different emotion annotations, instead of the 62 initially reported.

- Neutral co-occurrences increased from 1,396 to 1,412 after duplicate merging.

- Two repeated text occurrences remained within the validation set and none within the test set.

- All three exported Parquet files passed the schema, missing-value and label checks.

- We updated the notebook documentation to reflect these results and documented the limitations of our duplicate handling strategy.
